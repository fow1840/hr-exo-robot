## 0. 链路总览与组件映射

```
外骨骼(人) → MessageBridge → *_ee/target → Pink IK → joint_commands → 机械臂控制接口
机械臂 joint_states → FK 正解 → *_ee/state → 外骨骼反馈闭环
```

| 职责 | Walker S2 实证组件 | 本仓库对应 | 状态 |
|------|-------------------|-----------|------|
| 外骨骼→ROS2 话题桥 | MessageBridge（standalone 闭源，.2 容器） | `standalone/bin/ROS_2/MessageBridge` | 原样复用，配置见 README |
| 遥操作主程序（产生 target） | Puppetry（闭源，必须与 MessageBridge 同机走 IPC） | `standalone/bin/Puppetry` | 原样复用 |
| pink IK 逆解 | `pink_ws` + `robot_ik_retargeting`（ik_node_single_arm ×2） | `robot_ik_retargeting`（`ik_node` 双臂版，`g1_ik_retargeting.launch.py`） | 已迁入 |
| 关节状态→末端反馈 | `walker_s2_state_bridge`（.2） | `robot_fk_adapter/joint_to_pose_adapter` | 已迁入 |
| 500Hz 命令桥/安全门 | `walker_s2_pink_cmd_bridge`（.2，唯一命令源） | 无对应（本仓库 ik_node 直接发 `joint_commands`） | ⚠️ 差异，真机前评估 |

## 阶段 1：系统依赖（apt，真机一次性）

```bash
sudo apt-get update
sudo apt-get install -y python3.10-venv ros-humble-pinocchio
```

- `ros-humble-pinocchio` 是**硬依赖**（4.0.0，ROS jammy 官方源）。
  Walker S2 真机事故（2026-10-14）：未装它 → 双臂节点 `import pinocchio` 失败秒退，"进程未就绪"。
- 验证：

```bash
source /opt/ros/humble/setup.bash && python3 -c "import pinocchio; print(pinocchio.__version__)"
# 期望 4.0.0。若报 NumPy 2.x ABI 错误/段错误 = 系统 numpy 被升级到 2.x，见阶段 2
```

## 阶段 2：Python 依赖（venv，实证配方）

```bash
python3 -m venv --system-site-packages ~/pink_venv
~/pink_venv/bin/pip install -i https://mirrors.aliyun.com/pypi/simple/ \
    numpy==1.26.4 scipy==1.15.3 qpsolvers==4.8.2 proxsuite==0.7.2 \
    osqp==1.0.5 loop-rate-limiters==1.2.0 jinja2==3.1.6
~/pink_venv/bin/pip install -i https://mirrors.aliyun.com/pypi/simple/ \
    pin-pink==3.5.0 --no-deps     # --no-deps 是命门: 否则 pip 拉入遮蔽版 pin
```

三条红线（全部有真机/本机实证）：

1. **pip 的 `pin` 不得遮蔽 apt pinocchio**（P-016 M3：连续求解 native 崩溃）
2. **numpy 必须 1.x**（本机实证：numpy 2.2.6 下 apt pinocchio import 段错误）
3. **venv 必须 `--system-site-packages`**（否则看不到 rclpy/colcon）

## 阶段 4：四道门禁（launch 同款环境，全过才准进下一阶段）

```bash
ENVCMD="bash -c 'source /opt/ros/humble/setup.bash && source install/setup.bash && \
 export PYTHONPATH=~/pink_venv/lib/python3.10/site-packages:${PYTHONPATH:-}'"
```

| 门禁 | 命令 | 不过的后果（实证） |
|------|------|-------------------|
| A. pinocchio 可导入 | `$ENVCMD && python3 -c "import pinocchio"` | 双臂节点秒退"进程未就绪" |
| B. QP 求解器可用 | `$ENVCMD && python3 -c "import numpy,qpsolvers; assert 'osqp' in qpsolvers.available_solvers; qpsolvers.solve_qp(numpy.eye(2),numpy.zeros(2),solver='osqp')"` | 节点启动看似正常，离合使能瞬间崩溃 |
| C. numpy 版本 | `$ENVCMD && python3 -c "import numpy; assert numpy.__version__.startswith('1.')"` | pinocchio 段错误 |
| D. pink 版本 | `$ENVCMD && python3 -c "import pink; print(pink.__version__)"` | 3.5.0（与 500 步自检配方一致） |

## 阶段 6：真机分阶段上线（每步一验，可回退）

顺序与门禁取自 walker_s2_pink_teleop.sh 实证骨架，HR-UP 对应机制按 HANDOVER 待确认清单落实：

1. **记录当前状态**：机械臂姿态、运行进程、版本（部署门禁要求）。
2. **外骨骼桥启动**：MessageBridge + Puppetry（同机 IPC；跨机部署 IPC 不通，
   Puppetry 收不到末端 state，表现为 target 恒静默——Walker S2 实测）。
3. **状态流验证**：`ros2 topic echo --once /client_robot/joint_states`（无流则查会话/门控，P-015）。
4. **IK 节点启动**（PYTHONPATH 注入环境，见阶段 4）；
   等待日志出现 `initialized from live joint states`（从实测关节角初始化，防跳变）。
5. **FK 反馈验证**：`*_ee/state` 有数据，外骨骼侧可感知。
6. **命令唯一性门禁**：`ros2 topic info <命令话题>` 发布者必须为 0 后才允许启动命令发布，
   启动后必须为 1（双发布者 = 抢命令，实证脚本在启动前后各查一次）。
7. **离合/使能门禁**：双侧 clutch=false 才准啮合（啮合态启动会立即跟随目标，实证事故）。
8. **单臂低速**：先单臂、限速参数、安全位；啮合瞬间手臂应保持不动（帧差/标定错误会猛动）。
9. **双臂**：通过后才开双臂；全程急停可用、周围无人。
